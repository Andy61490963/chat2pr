# 維運

服務上線後的日常運作、處理方式與已知邊界。安裝、升級、備份還原與疑難排解的指令在 [部署手冊](deployment.md)。

## 自動運作與限制

安裝、升級、備份還原、停止與疑難排解的指令都在[部署手冊](deployment.md)。日常只需要知道：

- 監督程序每 30 秒檢查一次服務，Docker Desktop、容器、執行器或通道停了會自動拉回來；它由 Windows 排程工作 `LINE-AgentFlow` 在登入後啟動。要在前景觀察可執行 `npm run services`。
- 升級用 `npm run deploy`；想確認服務是否正常，隨時可以執行 `npm run smoke`。
- 每天自動清理一次 Docker：刪除超過 14 天、沒有專案或容器在用的 `line-agentflow-app`／`line-agentflow-worker` 舊標籤（`:latest`、`:local` 一律保留），清除懸空映像與超過 7 天沒用到的建置快取。不刪資料卷，也不動其他專案有名稱的映像；結果寫在看板的活動紀錄。只有正式實例的執行器會動手。
- 連線中斷、上游暫時無法服務這類錯誤會自動重新排隊，同一需求版本最多兩次，期間不發失敗通知；第三次仍失敗才通知。同一任務的失敗通知 30 分鐘內最多一則。
- 獨立審查只有「需要修改程式或交付內容才能解決」的問題會擋下發布；需要人、正式環境或真實資料才能完成的驗收會列在 PR 的「待人工確認」，合併前請自行檢查。
- 整台主機或入口斷線時 `app` 發不出通知，要靠[外部健康監控](deployment.md#外部健康監控)。
- 查看日誌：`docker compose logs --tail 100 app`、`.local\runner.log`、`.local\tunnel.log`。看板「系統」頁列出各服務狀態。

看板支援全域暫停、專案停用、取消與重試。設定的「AI 執行模式」另提供「暫停新需求判讀」：LINE 收訊與圖片下載照常，尚未判讀的訊息保留，已核准的任務仍可執行。儲存取消暫停後，才恢復彙整待處理訊息。已送出的判讀不承諾即時取消，但設定變更前的晚到結果不會建立或修改任務；全域暫停仍優先停止判讀與派工。新安裝及升級預設不啟用這個獨立開關。

全系統一次開發一個任務，每次最多 30 分鐘。訂閱模式以每日執行次數上限控管（預設 20 次）；API 模式預估上限為每次 US$3、每日 US$15，價格為應用程式估算，不保證供應商帳單絕不超額。兩者皆依臺北午夜重算。

原始訊息與圖片保留 30 天；撤回立即清除內容，相關需求重新審核。每天凌晨 3 點備份非原文資料並保留 7 份。專案的資料庫連線與結構快照不進備份，還原後到專案詳情重新登記並擷取。
備份加密使用本機 `sessionSecret`，請另外安全保存 `.local/secrets.json`，否則無法還原。

備份第 4 版另外包含需求的問題與假設；第 3 版已有成員名單、群組綁定、群組記憶與專案知識，還原後可重新建立向量。還原第 1～3 版時，問題與假設使用空值並提示核對原摘要。第 2 版備份沒有成員名單，還原後只有擁有者能登入，需重新加入成員；第 1 版另缺多專案綁定與記憶，須在啟用前由管理者核對。

## 使用摩擦指標

看板「系統」頁最上方的「使用摩擦」卡片，衡量使用者有沒有感覺到流程，可依期間（7／30／90 天）與群組篩選。全部從既有的任務、稽核紀錄、通知與訊息計算，不另外記錄資料。

| 指標               | 怎麼算                                                                                   | 方向     |
| ------------------ | ---------------------------------------------------------------------------------------- | -------- |
| 每件任務需要人回應 | 核准、拒絕、補充、指定專案、採用方案、修改假設、回答補問、改接、追加等稽核紀錄的平均次數 | 越少越好 |
| 每件任務要切到看板 | 同上，但不含在 LINE 回答補問                                                             | 越少越好 |
| 重講背景           | 沒有接上前一題、30 分鐘內又在同群組明確指名同一專案的任務數                              | 越少越好 |
| 接錯題             | 使用者改接對話串的次數                                                                   | 越少越好 |
| 第一則群組訊息     | 從訊息送出到機器人第一則群組推播的中位數；用 reply token 回的「收到」不留紀錄，不含在內  | 越短越好 |
| 查詢拿到答案       | 從提出到回答的中位數                                                                     | 越短越好 |
| 修改返工率         | 已合併的修改中，7 天內同一需求又追加修改的比例                                           | 越低越好 |

## 定期檢查

看板「定期檢查」頁可以設定每隔一段時間（最短 15 分鐘）或每天固定時間執行的檢查，狀態改變時才通知：

- **三種檢查**：
  - SQL 唯讀查詢：使用專案登記的資料庫連線，只在主機執行器執行，只允許單一 SELECT，並包在一定回滾的交易中；
  - HTTP 健康檢查：非 2xx、逾時，或回應不含指定文字就算異常；
  - TCP 連線檢查。
  - 本機回環、主機內部名稱與雲端中繼資料位址一律拒絕。
- **核准後才執行**：新建或修改後都是「待核准」，可以先「試跑」看結果；修改任何欄位都要重新核准。
- **執行時不呼叫 AI、不用 Codex 額度**。結果保留 30 天，不進每日備份。
- **通知**：
  - 只在變成異常或恢復正常時通知，持續異常不重複；
  - 預設發到群組並私訊管理者，靜音時段只通知管理者；
  - 每個檢查每天最多 6 則。
- **異常時請 AI 調查**：可選擇自動建立唯讀查詢任務調查可能原因，結果照查詢回報。每個檢查每天最多一次，會用 Codex 額度。
- **檢查本身出錯**（連不上資料庫、逾時）連續 3 次就暫停，只通知管理者，不會誤報成設備異常。
- **自動暫停**：群組停用、專案停用或解除綁定、系統暫停時不執行；恢復後不補跑錯過的次數。

## 日常處理

- 待審核：檢視來源、缺漏與敏感理由；先補充缺漏，再核准目前版本。核准舊版本會被拒絕。
- 敏感路徑：實際修改新增敏感檔案時會再次要求核准，核准僅涵蓋列出的路徑。重新執行會從記錄的基底建立隔離副本。
- 開發失敗：保留工作資料卷與執行紀錄，最多自動修復一次。人工重試前會核對 GitHub 遠端分支與 PR。
- 預留額度：辨識預留租約為五分鐘、開發為三十五分鐘；中斷的孤兒預留到期後回收，無法確認的費用保守計入預估用量。辨識會依圖片、上下文與輸出上限調整預留，逾時或缺少用量回報也會估算記帳。
- 群組辨識失敗：連續三次後停止辨識、保留原始訊息並通知。排除憑證或服務異常後，在群組頁按「重新辨識保留訊息」。
- 群組改綁或重新啟用：從新訊息開始，舊的未執行需求需要重新確認；不會突然處理停用期間的歷史對話。
- PR 建立時取消：已在傳輸中的 GitHub 請求可能完成，系統保留取消狀態，另以稽核紀錄與通知提供該 PR 連結供人工處理。

## 執行隔離

可信服務持有 LINE、OpenAI 與 GitHub App 機密。工作容器僅取得短效執行授權，代理限制模型、用途、版本、時間與剩餘估算額度。工作容器非 root、根目錄唯讀、無主機目錄及 Docker socket，並限制 CPU、記憶體與程序數。

安裝階段只能透過 Squid 代理連線至指定 HTTPS 套件來源；私有網路、主機及其他目的地均拒絕。套件白名單見 `infra/egress/squid.conf`。測試階段沒有網路。開發與審查僅連到內部代理網路；審查的工作副本唯讀。原始 Git 基底另外唯讀掛載，差異收集不信任專案可修改的 `.git`。

Codex SDK 在上述隔離容器內使用 `danger-full-access`，避免 Docker 禁止建立巢狀命名空間而使檔案操作失敗；此設定不可直接用於主機執行。安全邊界仍由 Docker 的非 root、唯讀根目錄、移除權能、隔離網路、唯讀審查掛載及限權代理強制執行。

目前工作映像包含 Node.js、Git、Python 與編譯工具。其他語言須建立帶 `io.agentflow.worker=v1` 標記且保留 `/opt/agentflow` 工具的映像，並重新驗證專案。私有套件需要另行設計限權下載方式，不能把主機或 GitHub 寫入金鑰傳入工作容器。

## 備份及還原（進階）

一般的備份、搬機流程見 [部署手冊的〈備份、還原與搬機〉](deployment.md#備份還原與搬機)；以下是手動指定資料庫的做法。

手動備份：

```powershell
docker compose exec app npm run backup
```

備份位於正式服務資料卷 `/data/backups`，包含設定、成員名單、專案、群組、任務與記錄；不含原始聊天、圖片、登入工作階段、執行授權或工作容器內容。每份檔案以 AES-256-GCM 加密，保留七個日期。

還原前停止派工，建立空白 PostgreSQL 資料庫並設定 `DATABASE_URL`，準備原本 `.local/secrets.json` 的 `sessionSecret`，然後執行：

```powershell
npm run restore -- C:\備份位置\agentflow-2026-11-04.afbackup
```

還原程式拒絕覆蓋有資料的資料庫；完成後保持全域暫停、群組停用、專案待驗證。原本進行中的任務轉為待人工處理，遠端 Issue／PR 不會自動重建。確認記錄與 GitHub 遠端狀態後，重新驗證環境、配對通知並逐步啟用。

成員名單自備份格式第 3 版起納入。還原更早的備份時，還原程式會提示名單未包含；此時只有擁有者能登入，須到看板重新加入其他管理者與成員。

不要使用 `docker compose down -v` 作為日常停止指令，這會移除資料卷。失敗工作副本可能包含專案機密與衍生資料，保留僅供排錯；系統會在保留期限到期後清理已結束執行的工作資料卷。

## 已知邊界

背景佇列保存外部錯誤時只保留固定格式的 HTTP 狀態或連線逾時／中止原因，不保存供應商原始 request、response、headers、body 或 cause。SDK 將逾時包成 HTTP 500 時，仍辨識有限的逾時原因；完整原始例外不應作為排錯附件。工作名稱、任務時間軸及服務狀態用來確認失敗階段，原有有界重試規則不變。

GitHub 一般 API 與 App 憑證取得請求，每次各有三十秒總期限，涵蓋等待標頭及完整回應本文；逾時會中止連線，不能把半截 JSON 當成成功。API 本文另有 64 MiB 上限，不影響有獨立期限與串流限制的專案封存檔下載。逾時不會讓後續請求沿用已失效的取消訊號。

本機完全離線時不能主動發送故障通知，恢復後才記錄服務心跳中斷。ngrok 狀態由本機連線與服務錯誤呈現，免費配額耗盡需由管理者在供應商後台確認；沒有自動購買或升級功能。模型列表可讀取只代表基本帳號權限，實際模型能力、價格與帳號配額仍須在串接驗收時確認。
