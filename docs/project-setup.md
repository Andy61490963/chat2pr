# 專案環境自動設定

新增專案預設由 AI 設定安裝與測試，不必先知道指令。既有專案保留原來的人工命令，不在升級時改變執行方式。

## 使用手順

1. 新增專案，選儲存庫、基底分支與工作映像，儲存。
2. 在專案詳情按「AI 自動設定並驗證」。系統依序顯示讀取設定、準備環境、安裝與基底驗證。
3. 成功後自動啟用派工。詳情可查看實際安裝／驗證命令、AI 說明、原始檔案引用及驗證版本。
4. 出現「建置通過；未執行自動測試」代表只證實可建置；之後的 PR 也會明確標示，不能當成測試已覆蓋功能。
5. 若缺少必要資訊，專案會顯示「等你回答」。到「專案資訊與環境」逐項補答，按「送出回答並繼續驗證」。看板鈴鐺與既有 LINE 管理者通知會提醒；等待期間釋放工作資源，不重複呼叫 AI。不要用正式資料庫測試。
6. 要沿用自訂流程時，編輯專案 → 展開「進階設定：手動安裝與測試指令」→ 選「手動指定指令」。修改設定後必須重新驗證。切回 AI 時原手動欄位保留，但不參與自動派工。

## 執行與版本

AI 取得固定 commit 的建置文件、套件清單、CI、鎖定檔雜湊、專案補充資訊與尚未合併的專案記憶。補充資訊列入設定雜湊；命令引用仍須對應儲存庫實際內容。機密位置、符號連結與管理者設定的敏感路徑不提供給模型。唯讀辨識 CI 不會改變修改 CI 時的風險審核規則。

回傳的引用必須存在於這次輸入。系統拒絕空驗證命令與明顯跳過失敗的寫法；自行新增的測試篩選只有在標示為部分測試並說明排除範圍時才接受。安裝與基底驗證若改動候選檔案，不發布自動設定。AI 不會刪除或修改測試；只有缺少真實資料或外部服務時才可以降為部分測試，並如實標示（見〈資料庫連線與結構快照〉）。

命令按專案設定版本、分支及建置設定雜湊重用；來源及套件仍使用既有快取。派工使用任務確認的分支，設定不同時重新判讀；修改任務先驗證新基底。查詢不因安裝設定而取得修改或發布權限。

保存成功設定與啟用專案在同一交易完成，設定版本變更會拒絕舊結果。驗證階段之間再次核對版本；同一專案的同時驗證由資料庫鎖去重，結束回收工作資源。既有需求審核、專案確認、全域暫停及容器隔離均保留。API 模式計入預留額度與用量，訂閱模式檢查服務帳號額度。

## 第一版範圍

自動判讀最多 60 份建置文件、單檔 24 KB、總計 100 KB；GitHub 樹截斷或超過範圍時要求手動指定，不根據部分資料猜測。支援映像中既有工具鏈；不自動取得憑證、建立資料庫或修改正式服務。沒有測試也沒有可執行建置流程時，需要補充資訊。

升級只新增 `projects.setup_mode`、`setup_plan`、`setup_status`；舊專案預設保留手動模式。自動設定結果與手動欄位分開保存，不會覆寫人工命令。本次不改工作映像或執行器協定，沿用隔離 AI 判讀與安裝、測試、收集介面。

## 專案資訊與環境、補問手順

在專案詳情填寫用途、分支說明、環境與相依服務、測試準備、操作限制及其他補充。資訊僅保存於看板資料庫，不自動開 PR 寫入 AGENTS.md；原本的「專案記憶」仍供開發規範使用。查詢與修改會收到相同資訊，任務的上下文來源可查看所用設定版本。分支說明不會自動改變任務的目標分支。

按「儲存資訊」只保存；按「儲存並驗證環境」會排程驗證。變更資訊增加專案設定版本，清除舊驗證與確認，進行中的舊執行不能發布結果。畫面過期時回傳 409，保留草稿供複製及重新檢視。補答與問題 ID、設定版本綁定，重複提交不會重複發布。

AI 缺少必要資訊時會列出最多五個問題。資料問題直接回覆非機密內容；登入、授權或驗證碼問題請自行開啟該服務完成，再勾選「已在服務完成驗證」。回報完成不等於服務已可存取，仍會實際重跑驗證。沒有通用的互動登入或驗證碼轉送通道，不收取、保存或轉送驗證碼，也不假設在瀏覽器登入就會替隔離容器授權。現有網路與權限不足時仍會停止。

請勿填入帳密、連線字串內的密碼、金鑰或驗證碼。API 會拒絕常見憑證格式，但格式檢查不能辨認所有機密；這不是機密保管庫。AI 提出的問題與既有操作權限互相獨立，不能因回答就略過測試、正式環境限制、預算或人工確認。

任務執行中若缺少必要資料，AI 以補問回覆結束本次工作。任務回到待審核、清除核准並釋放容器；看板與 LINE 通知列出問題。使用者在「補充需求」加入回答，再確認專案與需求後重新執行；不保留互動中的 shell。一般程式錯誤與測試失敗仍會呈現失敗證據，不把所有錯誤都包裝成缺資訊。

本次資料遷移新增 `projects.project_context`、`context_updated_at`、`context_updated_by` 與 `setup_input`。舊專案預設空資訊，升級本身不清除原有驗證；實際修改資訊才使驗證失效。

## 資料庫連線與結構快照

專案的測試需要資料庫、儲存庫裡又沒有建庫腳本時，在專案詳情的「資料庫連線」登記連線並擷取結構。這一步是選填的：沒有登記時 AI 會從程式碼推測結構自行模擬，不會停下來等人回答。

### 使用手順

1. 填入主機、連接埠、資料庫名稱、帳號與密碼，按「儲存連線」。目前支援 SQL Server。主機無法直接連到資料庫時勾選「經 SSH 跳板連線」，填跳板的主機、帳號與私鑰（或密碼）。
2. 按「測試連線」。成功時顯示伺服器版本與看得到的資料表數量；帳號缺少 VIEW DEFINITION 權限或擁有寫入權限時會提醒。失敗時顯示白話原因（連不上、登入被拒、權限不足、跳板驗證失敗）。
3. 按「擷取結構」。完成後顯示快照版本、擷取時間與各類物件數量。AI 自動設定的專案會作廢舊驗證並重新驗證環境，通過後恢復派工；手動指令的專案只保存快照。
4. 資料庫結構改了就再按一次「重新擷取結構」。內容沒有變化時不會升版，也不會動到既有驗證。

建議為這個用途建立專用帳號，只給結構讀取權限：

```sql
CREATE LOGIN agentflow_schema WITH PASSWORD = '請自行產生';
CREATE USER agentflow_schema FOR LOGIN agentflow_schema;
GRANT VIEW DEFINITION TO agentflow_schema;
```

### 擷取的內容

- 結構描述、自訂型別、序列、資料表（欄位、預設值、計算欄位、識別欄位）、主鍵與唯一條件、索引、檢查條件、外鍵、同義字，以及檢視、函式、預存程序、觸發程序的定義。
- **不擷取資料列。** 例外是擁有者在「參考資料表」明確列出的資料表，每張最多 500 列；適合狀態代碼這類不含個資的對照表，帳號要另外有該表的 SELECT 權限。
- 不含定序、檔案群組、分割、全文檢索、CLR 物件與資料庫層級設定。已加密或帳號讀不到定義的模組會略過，並在快照摘要列出數量。
- 整份快照上限 20 MB。

### 快照怎麼被使用

每次環境驗證與任務執行，快照都以唯讀資料卷掛在工作容器的 `/agentflow/env/database`（`schema.sql`、`foreign-keys.sql`、有參考資料時的 `reference-data.sql`，以及說明套用順序的 `README.md`）。AI 在同一個容器內啟動本機資料庫、套用快照、補上測試需要的虛構資料。環境規劃只會看到物件數量與資料表名稱，不會看到連線資訊。

測試需要 SQL Server 時，系統會自動改用含 SQL Server 的工作映像，在測試容器內啟動資料庫，並把專案寫死的 LocalDB 連線暫時導向它（不修改專案檔案）；判斷依據與覆寫方式見 [`docs/agents/project-environment.md`](agents/project-environment.md)〈自動選用與 LocalDB 導向〉。

測試用資料庫的來源依序是：

1. 儲存庫內的建庫、migration 或種子腳本。
2. 結構快照。
3. AI 從程式碼推測的結構。
4. 都不可行時只做建置檢查。

採用第 3 項時，專案狀態與之後的 PR 都會標示「資料庫結構由 AI 推測」。完整測試在模擬環境確實跑不了時，AI 可以只執行部分測試，但必須寫出排除了什麼與原因；專案狀態顯示「部分測試通過」，PR 的驗證段落列出未涵蓋的範圍。沒有說明就縮小範圍的設定會被拒絕。

資料庫或測試資料的缺口不再進入「等你回答」。AI 就這類問題補問時系統會攔下並要求改用模擬；只有提醒後仍無法進行（例如完全沒有資料存取程式碼可以推測）才會交給使用者。登入、授權與其他只有使用者知道的資訊仍照 #90 的流程補問。

### 安全界線

- 連線密碼、SSH 私鑰與密碼片語加密後保存在看板資料庫，金鑰由 `.local/secrets.json` 的 `sessionSecret` 衍生。API 只回傳主機、資料庫名稱等非機密欄位；機密不會出現在回應、活動紀錄、日誌、AI 提示詞或工作容器。更換 `sessionSecret` 後舊機密無法解開，需要重新填寫。
- 只有管理者能讀寫連線、測試與擷取，而且只能從看板操作。LINE 訊息、任務內容與 AI 都不能觸發擷取或取得連線資訊。
- 連線只由主機執行器發出，只執行讀取系統目錄的查詢；工作容器的測試階段維持無網路，不會連到真實資料庫。系統不提供寫入真實資料庫的路徑。
- SSH 跳板第一次連線成功時記下主機金鑰指紋，之後不同就拒絕連線；更換跳板主機或帳號會清除記錄並要求重新提供憑證。
- 連線與快照不進每日備份。還原備份後重新登記連線並擷取。
- 刪除連線會一併刪除保存的機密，已擷取的快照保留；刪除快照後 AI 自動設定的專案需要重新驗證。

本次資料遷移新增 `project_connections` 與 `project_schema_snapshots` 兩張表，並在 `SetupPlan` 增加 `dataSource`、`limitations` 與 `verification: "partial"`。環境規劃的設定版本提高，既有 AI 自動設定的專案在下一次驗證或派工時重新判讀。工作容器的程序數上限由 256 提高到 512，讓容器內的 SQL Server 可以執行。
