# 全流程驗收規格（Issue #37）

測試目標為 `example-org/test`，真實 LINE 群組為測試群組。原有群組綁定與自動辨識設定於測試結束還原。故障、壓力、舊日期與跨群組資料只在 `verify-<suiteId>` 隔離環境建立。不得中斷正式資料庫、模型、隧道或通知；不得新增付費資源、提高配額或自動切換 API。每個 Codex 任務仍以 30 分鐘為限。

這是 MES 前端快照，畫面驗收使用固定合成 MES 資料，不代表正式工廠後端已驗證，不部署工廠 IIS。

## 分階段發布與目前限制

訂閱憑證隔離、長推論傳輸與驗收啟動協定可獨立發布；圖片呈現語義的修正仍在 PR #46 驗收。舊判讀曾漏判未知授權語境，新解析器的圖片正向案例也尚未全部通過，不能把本次安全修復當作整體自動判讀已完成。

本輪正式續驗先保持全域暫停，部署後保存 `triage_paused=true`，確認沒有其他待執行工作，再續跑原有已核准需求。需求版本、原核准來源、敏感路徑、來源有效性、預算與獨立審查均保持原檢查。這個開關不會停下既有已核准任務或背景同步；不能以程序鎖或失聯後的補救暫停取代持久設定。恢復一般群組自動判讀前，仍須完成相應風險與圖片案例。

## 畫面門檻

每個 D 案例以 1440×900、768×1024、390×844、320px 窄螢幕檢查空、單筆、100 筆、超長中英文字、零、大數值、缺欄位及 API 延遲／失敗。固定資料、時間、縮放；記錄欄寬、遮擋、捲動、操作、JS 錯誤及資源載入。所有後端回應為合成資料，禁止連正式 MES。

before 必須來自固定 base SHA，after 必須來自 PR head SHA，合併後必須重新以 merge SHA 啟動預覽。PNG 可解碼且尺寸正確，須實際開啟檢視，GitHub PR 圖片也須顯示。只提到截圖或只有檔案不算通過。工具的 working-tree 模式可檢查未提交修改，但不能冒充上述三種版本證據。

## 結果規則

每例記錄案例 ID、輸入、預期／實際、環境、訊息／task／version／run／thread ID、圖片與 RAG 來源／分數／索引版本、Issue／PR、base／head／merge SHA、截圖、量測、耗時、用量、修復及缺陷。

明確區分真實 LINE、隔離重播、真實模型、服務替身、實際瀏覽器；混合環境逐層說明。最終狀態只使用「通過／失敗／受阻／未測」。重點正向、閒聊與圖片負向模型案例固定三次；保留首次結果，失敗修復後重跑不能刪去原失敗。重要案例未完成，不宣告整體完成。

合成基底的 core 40 組通過，但 strict 僅 6 組通過；長文字、大數值、對比與手機遮擋仍需 D 類真實開發修正。已保留低推論的 23 個探索結果，另以正式高推論設定完成 20 個模型子案、23 次呼叫；分類與檢索成功不能代替實際修改及畫面驗收。這批基礎及回歸通過不代表整份全流程驗收完成。

後續獨立複查發現，只擋已知能力詞仍會漏掉未知授權語境。因此登入不變豁免改為整段有限呈現語法：欄寬、對齊、文字呈現、手機捲動及明確不變條件之外，任何未知子句均保留人工審核。欄位標籤須在同段明確定義，不為單一測試欄名建立特例；不能跨請求沿用名稱。模型提出的風險與敏感路徑仍獨立攔截。四個跨組授權反例、未知及否定語境、通用欄名及隔離回歸皆保留首敗與修復結果，既有六次模型輸出重播通過；重播不等於新一輪真模型驗收。

逐句語法仍在正式高推論中產生合理描述的誤判，後續改用六種呈現語義解析器，完整消耗連接子句並檢查主詞及欄位引用。每輪固定六次的原始輸出及失敗都保留；局部回歸或獨立審查通過不能替代新一輪真模型驗收。

跨日圖片的畫面驗收另外保存只含表頭下方內距的合成圖片，七天前文字仍獨立提供欄寬與底色；新需求不得洩漏任何答案。先前漏手機圖的經驗由真 Execution、真容器測試和受控 code 替身產生失敗，再以可追溯快照匯入隔離歷史，不直接捏造失敗結果。日期、專案與群組映射需明列，不能宣稱是真實跨日 LINE 或真 AI 失敗。最終仍須取得兩類來源、原圖及相同過往結果，並通過實際畫面量測。
