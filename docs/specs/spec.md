# chat2pr 第一版規格

## 已確認需求

本機 Windows 持續運行，透過 ngrok 固定 HTTPS 網址接收 LINE Webhook。沿用 example-org 官方帳號 `@655zkxls`，機器人可加入多個群組；每個群組可綁定多個 GitHub 專案。所有群組成員均可提出需求，處理文字與圖片；符合群組觸發方式的訊息安靜 60 秒或距離批次第一則訊息 300 秒即彙整；全批次都是引用同群組機器人任務通知的文字追問時，安靜 5 秒即可排程，指令模式也不必加 `/任務`。

## 聊天室與群組觸發方式

群組預設 `trigger_mode=command` 且派工停用；管理者完成綁定與啟用後，文字必須以 `/任務` 開頭並接空白、換行、冒號或字串結尾才觸發。`auto` 模式辨識全部新訊息。所有訊息皆保存供聊天室閱讀；一般聊天在指令模式直接標記為不派工，不預留辨識額度、不呼叫模型，也不寫入群組／專案記憶。圖片下載使用獨立背景工作，即使群組或全域派工暫停仍可取得圖片。

收訊與群組設定使用同一個群組列鎖；訊息保存當時觸發資格。切換模式或啟停會結束尚未辨識的舊訊息，不追溯補派工；設定版本遞增，正在辨識的舊結果在交易內重新驗證版本，不能跨越設定變更。第一次升級將既有群組改成指令模式並結束未處理舊訊息，後續遷移不覆寫管理者選擇，既有任務不受影響。`PUT /api/groups/:id` 省略 `trigger_mode` 時保留原值。

指令可引用同群組、未撤回且未過期的訊息作為附件；圖片需先傳送，再回覆引用該圖並輸入指令。附件不獨立觸發，派工來源會同時保存指令與附件 ID，沿用撤回、到期、風險及版本檢查。引用不可讀的內容轉人工確認。模型不能把只有附件、或屬於另一指令的附件當成獨立工作；其他一般聊天只能作為背景。自動辨識把無需求的貼圖略過，不因附件格式不支援就製造待審核任務；無法讀取且送入辨識的圖片仍保守轉人工確認。

管理 API `GET /api/groups/:id/messages` 每頁 50 則，`before` 使用同群組訊息 ID 游標，以收訊時間與 ID 穩定排序；回傳去識別發話者代號、文字、圖片狀態、引用 ID、處理狀態與同群組相關任務。圖片沿用 `GET /api/messages/:id/image`。兩端點皆驗證管理者登入且不快取；查詢時即時遮罩撤回與過期內容，不依賴清理工作完成。聊天異動版本加入 SSE；頁面重取已載入分頁，撤回圖片同步離開放大檢視，並每 30 秒補查到期狀態。看板不提供發訊功能，也無法取得機器人加入前的 LINE 歷史。

需求辨識依專案說明、儲存庫檔案結構與群組記憶，判斷每個需求要修改哪個專案；只綁一個專案時直接使用。無法判斷時建立待指定專案的任務，由管理者在看板選擇，並可一併記住規則。群組成員明確要求「記住」的指路規則直接寫入群組記憶，不建立任務；記憶只能指向該群組已綁定的專案，管理者可在看板新增或刪除。

群組要求記住的專案開發規範、程式風格與背景知識存為專案記憶：開發與審查時直接帶入，並由服務以固定分支的 PR 寫進該專案的 `AGENTS.md`，人工合併後長期生效；不建立任務。

群組對話常是碎片化的。判讀時提供近三天最多 300 則對話、被引用的舊訊息，以及群組所有未結束與近 90 天的任務，讓 AI 合併同一件事的多則訊息。明顯沒說完的訊息可暫緩，與之後的訊息一起判讀；等候超過 15 分鐘不得再暫緩，仍不明確時轉人工確認。補充尚未開始的需求時併入同一任務成為新版本；原需求已開始則另建追加事項，不改動進行中的版本。

修改一律先在看板人工確認；查詢依明確專案證據與機密規則決定能否自動執行。閒聊不派工，不確定或無法讀取的附件轉人工。資訊缺口先區分可查證資訊、合理預設、必要問題與產品方向：可查的交給執行階段，合理預設列入摘要的假設，只缺必要資訊就問一個問題並可附常見答案。只有修改的產品方向不同才提供選項、唯一推薦與理由，查詢不產生開發方案。方案採用只在看板確認；敏感需求仍需補充後核准，LINE 不直接核准修改。來源必須屬於同群組，核准綁定需求版本。改派專案會產生新需求版本，須重新核准。

每個有效需求一張目標儲存庫 Issue；Codex 在獨立容器修改固定基底 commit，執行測試與獨立程式審查，失敗最多修復一次。若獨立審查未通過，錯誤摘要優先列出審查原因，避免被長篇測試日誌截斷。可信服務推送分支及建立 PR，人工合併，絕不自動部署。相同事件／執行重試不可重複建立 Issue 或 PR。

## 介面與權限

敏感規則檢查需求題目、摘要、全部驗收條件及來源文字；模型回覆空風險不能掩蓋其中的敏感修改。完整的「保留既有登入功能」可作為一般外觀調整的保留條件。有限呈現解析器辨認欄寬、對齊、文字可讀、捲動、不變條件及圖片標註六種語義，必須消耗全部子句；省略主詞或指定寬度只能引用同一請求已成立的呈現條件。未知授權、未解析字詞或否定仍保守審核，不能只因模型聲稱安全就通過。例外只遮罩已證明不變的登入片段，真正的登入、權限、驗證、session／cookie 等變更、模型風險及敏感路徑始終保留人工關卡。

位置名稱、圖片參照前綴及未引號英文欄名共用名稱守門，不能吞掉群組／角色／使用者主受體或自然語言動作。未引號漢字原子最多四字，較長字串只接受有限 UI 名詞組合；其他長名稱需以「名稱」或『名稱』明確引用，否則保留人工審核。引號只表示資料標籤，原文敏感詞仍檢查。這是保守的呈現語法，不是任意自然語言的安全判定器。

文字閱讀與既有捲動操作沿用上述呈現範圍。「無截斷、裁切或遮擋」只可補充前一句已辨識欄位的可讀條件，不能泛化為任意否定或權限豁免；其他欄位的文字、資料或設定維持原狀，也不能用來允許新增的管理操作。

繁體中文手機友善看板：收件匣（待指定專案、待審核、失敗與等待額度的工作，以及進行中與待合併）、任務、群組（綁定專案與記憶）、專案、設定（AI 執行模式、服務連線、私訊配對）。提供補充、指定專案、核准、拒絕、取消、重試、專案／全域暫停。只有擁有者（`.env` 的 `ADMIN_GITHUB_ID`）可以管理。以短效一次性碼綁定管理者 LINE 私訊身分，只通知待決策、異常及 PR 完成。

GitHub App 僅安裝於指定專案；同一 App 可安裝在多個帳號或組織，服務依儲存庫找對應安裝。執行容器不可取得主金鑰、主訂閱登入、GitHub 寫入憑證、LINE 機密、Docker socket 或主機目錄。訂閱與 API 呼叫皆使用有限推論授權，訊息、圖片與儲存庫資料不能改寫系統權限。

## AI 執行模式

提供訂閱與 API 兩種模式，為全域設定，預設為訂閱模式，由管理者於看板切換；切換只影響之後開始的判讀與執行。

管理設定 `triage_paused` 代表「暫停新需求判讀」，新安裝與缺少此欄位的升級資料補為 `false`，既有值不覆寫。只有登入的管理者可透過設定 API／看板變更；舊呼叫端省略欄位時保留原值。啟用期間不排新的判讀工作，已在佇列中的判讀亦會於入口停止；讀取專案上下文後、呼叫模型前再次核對設定，提交結果時以交易鎖檢查開關及設定 revision，包含暫停後又恢復的舊結果也不得建立或修改任務。已送出的 AI 呼叫不保證即時中止，待處理來源仍保留，恢復後重新彙整。LINE 文字收訊、背景圖片下載與已核准任務執行不受此開關影響；原有核准版本、來源、風險路徑、用量及執行守門完整保留。`paused=true` 的全域暫停仍優先停止判讀與派工。

訂閱模式以 Codex（`@openai/codex-sdk`）搭配服務專用的 ChatGPT 登入，用量計入訂閱方案限額，並與管理者自身的 Codex 使用共用，不需 API 金鑰。需求辨識在不掛載儲存庫的一次性容器內以唯讀沙箱執行，輸出須符合固定 JSON Schema。API 模式以 OpenAI API 金鑰呼叫，依預估金額記帳。

訂閱登入檔（`auth.json`）視同密碼，只存在可信主機的 `.codex-service/`，由主機上的官方 CLI 讀取與刷新；不得注入工作容器，也不接受工作輸出回寫登入。工作容器使用自訂 Responses provider，僅持有當次階段的短效能力權杖。可信代理綁定工作、階段、模型與期限，累計同工作的請求、輸入及輸出用量，取消、清理及異常串流會撤銷授權。主憑證不得進入 Git、日誌、測試快照、應用程式或轉送容器。達方案限額時停止 AI 但仍接收訊息，工作保留並每小時重試；不自動改用 API 模式。

訂閱代理只連固定的 ChatGPT Responses 路由，不接受重導向或遠端工具。上游事件及用量在有界緩衝中驗證後才交給工作容器，缺少完整結果、用量不合法或連線中斷不能當成功。應用程式限制並不等同供應商帳單承諾，也不提高既有每任務三十分鐘與預算門檻。

訂閱上游使用原生 HTTPS 串流，等待標頭及讀取本文都受同一階段的剩餘期限控制，不另套用短於任務期限的五分鐘標頭等待。取消會中止請求及回應串流；輸出大小與事件用量仍經代理的完整檢查，傳輸層不保存無界回應，也不跟隨重新導向。

HTTP 429 及真正 `error`／`response.failed` 事件中的已知 `usage_limit_reached`、`rate_limit_exceeded` 代碼會轉成不含上游原文的額度錯誤，沿用共用額度關卡停止新呼叫。未知錯誤仍失敗；一般模型文字或錯誤訊息提及額度，不作為額度判定依據。

## 執行環境

每次判讀與執行使用拋棄式 Docker 容器，結束即刪除容器。映像檔包含 Node、git、Python、無頭 Chromium 與 Playwright（供截圖驗收）及固定版本的 Codex CLI；開發階段不能下載工具，需要的工具一律預先裝進映像。專案環境驗證及開發改由可信快取工具取得固定基底 commit：首次淺層抓取、相同 commit 重用本機物件及快照、新 commit 增量抓取。每次仍建立獨立可寫 volume 與唯讀比較基底，不共享工作目錄、硬連結或 Codex 對話。容器輸出變更檔案、測試結果與審查結論，由可信服務推送分支及建立 PR。

原始碼快取以 GitHub App 安裝、儲存庫固定 ID 與名稱隔離。每次包含命中都重新取得單一儲存庫、contents 唯讀的短效憑證，不能用快取繞過已撤銷的授權。憑證只以 stdin 傳入 `infra/source` 建立的可信映像，不使用專案指定映像執行下載、不寫入 URL／Docker 環境變數／Git 設定／副本。快取工具不執行專案命令，Git hooks、系統設定與套用濾鏡均停用。同一快取用 flock 串行操作，快照完成後才更新標記；中斷留下的鎖與暫存 pack 在取得 flock 後清理。準備逾時納入任務剩餘時間，取消會清除同一執行識別碼的工具容器。快取只存於專用 Docker volume，工作容器與每日資料備份都不包含它；移除快取只影響下次準備速度。

安裝階段只能經 `egress` 連到套件來源；訂閱模式的 AI 階段位於專用內網，只能透過固定轉送服務呼叫主機訂閱代理，不加入舊的 AI 出口網路；測試與差異收集階段無網路。服務以獨立的 `CODEX_HOME` 另行登入，撤銷服務登入不影響個人使用。容器本身為隔離邊界，容器內 Codex 以完全存取模式在唯讀根目錄、非 root、無額外權限下執行；這個模式不構成將主登入檔放入容器的例外。

第一版於主機 Docker Desktop（WSL2）運行；開放更多群組前，評估將整套服務移入 Hyper-V Linux 虛擬機。

## 用量與維運

全域一個開發任務。每次最多 30 分鐘（含一次修復）。訂閱模式以管理者設定的每日執行次數上限控管，看板顯示 Codex 回報的各額度窗口使用率與重置時間，並可設定模型與判讀／開發的思考程度；API 模式每次預估 US$3、每日預估 US$15，先預留再記帳。兩種模式皆於臺北午夜重算，超額停止 AI 但仍接收訊息。此門檻非供應商帳單或方案限額保證。原文、圖片及上下文快取保存 30 天，撤回即移除原文並重新審核相關工作。非原文資料每日備份、保留七份。Windows 登入、Docker 啟動後恢復服務；中斷工作需核對遠端狀態。

## 驗收邊界

Webhook：簽章、重送、撤回、跨群組隔離及彙整。專案路由：只能指定群組已綁定的專案、無法判斷時待管理者指定、聊天記憶與管理者記憶、單一專案預設。管理 API：登入、CSRF、需求版本、重複審核、設定驗證及刪除。工作流程：風險、一次修復、逾時、預算、恢復與外部副作用去重。AI 執行模式：訂閱限額暫停與恢復、不自動改用 API 模式。容器：兩種模式下的權限、機密隔離與對外連線限制。畫面：手機操作與真實 API。外部真實驗收：LINE → 本機 → Codex → PR → LINE 私訊，完成後再啟用其他群組。

## 本機向量基礎設施（第 0 階段）

管理者可在 AI 設定開啟本機 RAG，透過服務連線檢查驗證中文推論。正式安裝與既有資料庫升級均預設關閉；舊版設定請求省略開關時保留原值。模型逾時或回傳無效向量時只更新這一項服務狀態，應用程式仍可收訊與派工。

模型服務只在應用程式的專用內網提供推論，透過一次性初始化容器下載固定版本。PostgreSQL 以 1,024 維向量與 HNSW 餘弦索引保存可重建資料；對話、任務與記憶只存參照與向量。只有專案檔案與任務結果允許寫入內容，所有向量均排除於日常備份。專案程式檔案與任務經驗索引分別在第 2、3 階段實作。

## 判讀時找回舊資料（第 1 階段）

啟用本機 RAG 後，文字訊息、任務（標題、需求與驗收條件）、群組記憶與專案記憶的異動，會在同一筆資料庫交易留下待處理的來源識別碼。背景 `embed` 佇列才讀取原文並執行推論；若期間來源更新或撤回，舊結果不得寫回。停用時不自動建立或查詢向量；管理者仍可手動補建現有資料。索引可重建，不列入每日備份。

判讀以當批文字及其引用訊息搜尋，以餘弦相似度排序、時間遠近作小幅調整。最多取同群組舊對話 20 則、任務 10 筆、群組記憶與綁定專案記憶各 5 條；排除當批、近期上下文和已帶入的引用訊息。檢索上下文合計最多 20,000 字元。資料從來源即時讀取，撤回、逾期或解除綁定後不得再提供。模型故障只記錄服務狀態；判讀依舊使用原有流程，不因檢索故障增加該群的失敗次數。

每次判讀在時間軸記錄檢索筆數或略過原因。任務詳情依保存期限和目前綁定，顯示相關任務識別碼、標題與舊訊息時間；不複製原文到稽核紀錄。設定頁列出各類索引筆數、補建進度與最近完成時間。

## 判讀時參考專案檔案（第 2 階段）

本機 RAG 啟用時，已綁定專案通過環境驗證，或需求判讀讀到新的基底 commit，便排程 `repo-index`。工作在應用程式容器串流解壓 GitHub App 下載的固定版本封存檔，只收支援的 UTF-8 原始碼與文件。一般檔案最多 200 KiB，JSON 必須小於 100 KiB。略過建置目錄、相依套件、鎖定檔、壓縮腳本、二進位、已知憑證格式及專案設定的敏感路徑。

封存檔連線及等待下一批資料各有 60 秒停滯上限；有持續進度的大型下載可執行至 30 分鐘總上限。下游解壓背壓不算網路停滯。完成、失敗或下游取消都會清理計時器並釋放串流；看板保留固定且不含機密的逾時原因，失敗不公開部分向量版本。

每段最多約 1,500 字元，按行切割，相鄰段落盡量保留 200 字元重疊；單行過長時保留相同行號分段。每個版本最多 5,000 段，超過時記錄實際段數及上限，不發布截斷索引。在本機 CPU 上，同一專案的路徑詞、識別字與中文詞共用 BGE-M3 詞向量，再依各段用詞與詞頻合成向量。資料庫另存片段原文、路徑與行號。工作完成才切換可查詢版本並刪除舊片段，解除最後一個綁定、刪除專案或調整環境設定時清除索引。

管理者可設定 `projects.index_paths`，最多 50 個儲存庫相對檔案／目錄路徑，按完整路徑或目錄邊界匹配。空陣列為全儲存庫；建立專案未指定時預設空陣列，舊版更新 API 省略時保留既有值。API 正規化尾端斜線、排序及重複項目，API 與資料庫均拒絕跳層、絕對路徑及萬用字元。變更範圍增加設定版本、作廢環境驗證與舊索引，推論中的舊 generation 不得重新發布。指定路徑沒有任何合格文字（包含被敏感規則完全排除），或總數超過上限時，不發布空白或部分索引。完成狀態與看板明列所選範圍，不能宣稱全儲存庫皆可檢索；範圍不改變 Codex、原始碼下載或快取權限。

判讀只讀取群組當下綁定、且與 GitHub 回報基底 commit 一致的完整索引。依向量相似度、不同路徑詞的匹配數及原文選出每個相關專案最多五段，同一路徑最多兩段，合計上限 15,000 字元。明確英文欄名等連續二至四詞的詞組，以完整詞邊界匹配，給固定且不累加的額外分數，避免頁首只因共用路徑就擠掉實際欄位片段；重複查詢詞不重複加分。純中文查詢仍沿用向量與中文詞判斷，不要求英文命中。分類器將片段視為專案資料，在專案路由和產品方向建議中引用相符的檔案。

## 開發與審查參考過往結果（第 3 階段）

任務進入待合併、需要處理（執行失敗）或已合併時，由背景工作索引標題、需求、最後審查或失敗原因及合併狀態。結果摘要最多保留各欄位的限定長度；截至目前仍屬於專案的資料才可使用。狀態或版本變更會立即使舊向量失效，合併通知與重試都沿用同一個任務識別碼。舊資料可在設定中補建。

開發和唯讀審查共用同一次取出的 `pastOutcomes`。最多三筆，依相似度排序，排除本任務與其他專案，且重新檢查來源群組與執行群組各自的專案綁定。過往經驗只用來提醒驗證，所有派工、權限、變更範圍及預算仍由現行規則決定。模型離線時記錄服務狀態並繼續開發。

新綁定或啟用本機 RAG 時會在背景預先建立已驗證專案的檔案索引。遇到新基底時，第一批訊息保留等待索引完成，從首則訊息起最多五分鐘。若模型故障或已到等待期限，則以現有對話繼續判讀。

## 唯讀執行監看

每次派工保留獨立執行 ID、需求版本、設定模型、目前／最後階段、起訖與期限、心跳及結束結果。SDK 使用 runStreamed 取得 thread.started、命令開始／結束、檔案修改、公開回覆、用量及錯誤；不保存內部推理、原始提示詞、工具完整參數或登入檔。開發與獨立審查建立不同 thread，不能把本機 SDK 的識別碼當成雲端 Codex 任務網址。

工作容器事件經專用 stderr 前綴送到可信執行器，在白名單結構驗證、憑證遮蔽與長度限制後暫存。應用程式每兩秒以執行器憑證讀取增量，依執行 ID、來源及序號去重保存；階段回覆另附事件，補回快速結束階段。進度讀取失敗不能停止原工作或宣告成功；讀取恢復留下紀錄。重啟後保留已保存事件，最後階段與中斷結果分開呈現，不盲目重跑。

管理者以 GET /api/tasks/:id/runs/:runId/events 讀取最近 200 筆，before 游標讀取較早紀錄，驗證登入白名單及執行所屬任務。既有 SSE 通知包含執行心跳和事件異動。瀏覽器沒有執行器憑證、Docker 存取權或 Codex 控制端點；任務詳情 API 不再回傳 runs.result 中的原始檔案與內容。

事件內容最多 6,000 字元，主機每個執行最多 2,001 筆（包含截斷提示），暫存至多 64 個執行並於兩小時後淘汰。資料庫查詢即時排除超過保存期限、來源撤回／缺失／到期的內容；撤回時清除、維護時補清除，延遲事件不得把內容寫回。執行識別碼與不含原文的階段資料留作診斷，run_events 不列入每日備份。此功能上線前的舊執行明確標示未保存資訊，不能反推出歷史 thread ID 或底層網路原因。

## PR 驗收附件呈現

每次變更維持最多 200 個檔案、原始內容合計 10 MiB。開發提示明列此限制，完整瀏覽器矩陣的中介 PNG 留在暫存區；提交必要代表圖（四種尺寸的 before／after 最多八張）及完整精簡數值結果。不得自動刪去超限候選或降低驗收條件。收集前先統計所有變更，超限時回報總量與有界大檔清單；結構化收集回應最多 16 MiB，以容納 base64 與差異中繼資料，超限明確失敗，不以截斷 JSON 當作成功。一般執行日誌仍維持原上限。

開發、修復與獨立審查取得相同 `sourceVersion`，包含儲存庫、基底分支與可信遠端 commit。容器的本機 Git 基底可能有不同 SHA，驗收報告不得將其冒充遠端版本；需另列本機識別，最終 before／head／merge 圖片由固定遠端版本的獨立工具驗證。

差異預覽上限為 150,000 bytes，另列完整長度及截斷旗標。獨立審查從唯讀基底與候選重算全部變更，核對收集時的前後 SHA-256、內容長度與檔案模式，再於暫存區建立逐檔完整差異及原始內容；不信任候選內的 `.git`。新增、刪除、模式變更及二進位圖片皆列入清單；文字差異不受專案屬性隱藏。審查證據含清單最多 64 MiB、基底單檔最多 32 MiB，超限或不一致立即停止，不以部分證據通過。

發布前審查核對程式、測試、必要圖片與本階段可驗證的結果；PR 網址、固定 head 與合併後畫面則由發布後驗收核對。尚未發布本身不是程式審查失敗，亦不能宣稱發布後驗收已通過。缺少完整可信差異、必要圖片或有效驗收證據仍須拒絕。

應用程式至執行器的 HTTP 請求使用階段剩餘時間作總期限，涵蓋連線、上傳、標頭與完整回應；另留十秒接收中止及清理結果，不延長工作容器期限。取消與回收請求另限二十秒。連線不跟隨重新導向，回應超過 32 MiB、斷流或 JSON 不完整均失敗，完成與中止會回收來源及 socket。API 模式的 HTTP 429 保留 API 錯誤，不誤判成訂閱額度暫停。

發布流程從已通過驗證的變更清單選取未刪除的附件：`docs/`、`screenshots/`、`artifacts/` 的常見點陣圖片提供預覽，`docs/` Markdown 提供文件連結。固定到分支實際提交 SHA；遇到相同檔案樹的既有分支，連結使用該分支的既有提交。before／after 同組檔案並排，其他圖片單獨預覽。排除敏感與不安全路徑，最多 8 張預覽、32 份連結，附件區段約 24,000 字元為上限。沒有附件不捏造圖片，也不把圖片存在宣稱為驗收通過。既有 PR 保留人工編輯內容。

## 訂閱額度與服務中斷

訂閱額度以資料庫共用檢查狀態，在圖文判讀及每次開發、修復、審查前驗證。只有近期且明確的 `allowed=true` 可通行；耗盡、登入失效、離線或未知回應均保留工作。正向快取 30 秒、阻擋快取 60 秒；執行途中首次遇到供應商用量上限會立即使共用狀態失效，後續任務不能各自再嘗試推論。等待工作只在重新確認額度可用後續跑，不改動全域暫停、AI 模式或預算，也不切換到付費 API。

看板處理隧道及代理錯誤時先確認 HTTP 狀態及 JSON 內容型別，遇到 HTML 或損壞 JSON 顯示繁體中文錯誤，不顯示代理頁面或解析堆疊。SSE 重新連線成功時重新載入狀態，恢復後移除舊錯誤；登入失效仍清除管理者畫面。

## 圖片記憶與版本證據

只有實際參與需求辨識的圖片才產生結構化觀察：來源 ID、可信服務計算的原圖雜湊、辨識文字、畫面摘要、不確定事項及意圖分類。觀察是原始訊息的衍生資料，不改寫 LINE 文字、不等於核准或永久專案規範。指令模式的一般圖片不呼叫辨識模型。

`image_observations` 獨立保存觀察；`embeddings.kind=image` 僅存來源參照及向量，不保存觀察內容。檢索立即檢查同群組、原圖雜湊、撤回及保存期限，再把有效候選原圖交判讀。明確選定才能加入任務，候選不唯一、截斷後無法確認唯一性或依賴失效歷史時轉待確認。

`task_image_refs` 按任務及需求版本固定圖片 ID、原始雜湊、格式、直接／檢索引用方式與觀察 ID。版本變更只複製仍屬新版來源的引用；判讀可建立新版引用。開發、修復、獨立審查共用同組經驗證圖片，工作容器收到 SDK 的實際 `local_image`。每階段及可信發布前重新驗證版本、綁定、期限、撤回、格式及原始雜湊。無法驗證就停止，不以摘要假裝取得原圖。

圖片下載實際解碼，限制 10 MB／4,000 萬像素；模型一次最多六張與 30 MB。GIF 轉首幀 PNG 供模型使用，另記模型輸入雜湊，原始 GIF 及來源雜湊保持不變。撤回或過期會刪除原圖、觀察及向量，索引期間晚到結果不得重建失效資料。日常備份排除圖片觀察、向量、圖片引用及上下文證據。

`task_context_evidence` 只保存來源類別、ID、時間、分數、檔案行號與索引 SHA，不保存提示詞／原文。介面分辨近期對話、直接引用、資料庫記憶、向量檢索、過往結果；顯示來源是否仍有效。命中及提供模型只代表可核對的輸入證據，不宣稱模型必然採用。詳情端點限管理者，回應不快取。

## 驗收 instance 隔離

正式 instance 為 `production`，驗收為 `verify-<suiteId>`；容器、卷、來源快取、網路均綁定 instance。清理、取消、回收必須核對 instance 與工作 ID；未標記的舊資源不能自動刪除。驗收 runner 啟動前要求 instance 專用設定與登入目錄、獨立授權及非正式埠。不同資料庫、佇列和故障代理分開運作，真實 Codex 任務仍序列執行。

驗收啟動器在保存登入副本前檢查所有入口埠及專用訂閱轉送映像，並將映像固定為不可變 ID。沿用已啟動 runner 時，健康回應必須同時符合 instance、成功狀態與 `subscriptionBroker: "v1"`；舊協定或不明回應直接停止啟動流程。只有明確連線遭拒才建立新程序，避免逾時重啟導致既有工作被清理。

容器作業以同一截止時間涵蓋建立、連線、啟動、等待及輸出，Docker 呼叫本身未返回也必須結束等待；晚到的容器或連線只能清理，不得重新啟動或補送憑證。容器移除後必須確認實際消失，才能清除其工作卷；Docker 暫時回報 409 時採有界重試，且每次重新核對資源歸屬。清理本身亦有期限，故障不得蓋掉原本的準備失敗、任務逾時或執行原因；未完成的資源保留供後續核對重試。

驗收採固定 manifest 與追加式結果紀錄，可從中斷點核對後續跑；首次失敗必須保留。結果分真實 LINE、隔離重播、真實模型、替身與瀏覽器。重要案例未測或受阻不能宣告整體完成；完整矩陣見 [全流程驗收規格](full-flow-acceptance.md)。
