# 使用指南

日常在 LINE 群組與看板上怎麼用。部署與維運見 [部署手冊](deployment.md) 與 [維運](operations.md)。

1. 把這台伺服器的 LINE 機器人加進群組（每台伺服器各有自己的機器人），在看板「群組」頁勾選這個群組可以修改的專案。
2. 群組預設「指令與引用追問」：例如 `/任務 把首頁按鈕改成綠色，保留點擊功能`。安靜 1 分鐘（最長 5 分鐘）後，AI 整理需求並選擇專案；一般聊天只保存、不呼叫辨識模型。在「群組」頁可改選「自動辨識」。
3. **修改程式一律先確認目標專案**：收到 LINE 通知後，進看板任務詳情核對完整儲存庫、需求與理由，按「確認專案並核准修改」。只有一個綁定也不能省略確認。
4. 需求不夠明確時，AI 先區分可查證資訊、合理預設、必要問題與產品方向；只缺資訊時，任務詳情顯示一個問題與最多三個常見答案。程式碼可查的資訊交給執行階段；合理預設寫進摘要與「我先這樣假設」，可按「修改」直接調整單一假設，儲存成新版本並重新確認。只有修改的產品方向確實不同時才提供選項、推薦與理由；查詢不提供開發方案。LINE 只提供通知與看板連結，舊版採用按鈕也不會直接派工。
   - **在原地回答**：判讀或 Codex 執行中缺一件事時，機器人會在提出需求的群組發問（群組設定不回覆時只通知管理者）。群組成員用 LINE「回覆」那則提問直接作答，或在看板任務詳情點常見答案、輸入後按「送出回答」。系統把問答併進需求成為新版本：查詢照原本規則直接繼續，修改需求仍要管理者確認。回答含密碼、金鑰等憑證格式時不會被收下。
   - 已回答的查詢修改「我先這樣假設」時，按「依新假設接著問」會建立新的一題並保留原回答；新題沿用原專案、分支與對話串，索取機密實際值時仍要等人工確認。尚未回答的任務則修改原需求並產生新版本。
5. 只想查資料、問問題時，AI 會建立**查詢任務**：本次明確指名唯一專案，或有唯一有效檔案證據時可自動執行；其餘先到看板確認。報告標明專案名稱與儲存庫，顯示於看板、GitHub Issue 及 LINE，不開 PR。切換查詢／修改類型會作廢舊核准。
   - **指名寫法**：完整儲存庫（`example-org/OrderService`）、專案名稱，以及在已登記專案中唯一、至少 6 個字的儲存庫名稱（`OrderService`）或去掉結尾括號的專案名稱都算。
   - **風險**：查詢在隔離容器唯讀執行，回答會遮蔽機密，所以詢問權限、部署、密碼儲存方式等功能怎麼運作不會被擋；只有要求交出密碼、金鑰、token、連線字串等機密的實際值時，才等人工確認。AI 對查詢列出的風險記在活動紀錄當提醒。修改任務一律人工確認，規則不變。
   - **跨專案查詢**：明確指名多個已綁定本群組的專案時（例如比對兩個專案的欄位），可自動執行；其他專案設定分支的最新版本會唯讀放在 `/agentflow/env/projects/<儲存庫名稱>`，報告開頭列出「一併查詢」的專案與版本。指名未綁定的專案仍會擋下。
   - **安裝依賴**：失敗時自動重試一次；查詢重試仍失敗時改以閱讀程式碼回答，並在報告註明哪些部分未實際執行。修改任務重試仍失敗就停止。
   - **追問**：查詢回答後可以接著問，不用再寫專案名稱。
     - 在 LINE 用「回覆」引用同群組機器人的任務回答後輸入問題，例如「那 ch3 呢？」；指令模式也不必加 `/任務`，並會立即回覆收到。或在看板任務詳情的「接著問」輸入。
     - 待判讀訊息全是這類文字追問時，安靜 5 秒後即可排程；混有一般需求或圖片時，維持安靜 60 秒／最長 300 秒。實際開始仍受佇列與額度限制。
     - 系統會建立新的一題，沿用上一題的專案與分支，並把前面的問答交給 Codex，原本的回答會保留。
     - 沒有引用時，AI 會判斷是不是接續 7 天內的某一題；有指名其他專案就不沿用。
     - 索取機密實際值的追問一樣要等人工確認。對話串沒有題數上限；交給 Codex 時，最近 5 題給完整問答，更早的只給問題與「先看重點」。
     - 接錯題時，在 LINE 改引用正確的那則回答，或在看板任務詳情的「接錯題了？」改接到正確的上一題（或改成新話題），系統會重新處理。
     - 看板的「修改問題重新查詢」會**取代**原回答，只在想換個問法整個重查時使用。
6. 分不清專案時，到任務詳情「更換專案」。需要留下長期規則才另外勾選「記住」（預設不勾）；也可以說「`/任務 記住：報工相關都改 MES 前端`」。群組記憶可供 AI 參考，但不能單獨作為自動派工依據。
7. 專案開發規範可在群組提出，例如「`/任務 記住：MES 前端不要用 jQuery`」；系統建立修改 `AGENTS.md` 的待確認任務，確認專案後才執行並開 PR。
8. 自動辨識可彙整零碎聊天；指令模式的補充需以 `/任務` 開頭，或引用同群組機器人的任務通知。AI 會讀近三天對話作為背景，但只有符合觸發規則的訊息才能提出新工作。話還沒說完會先等，補充尚未開始的需求會併入同一張任務；修改任務仍須確認新版本。
9. PR 完成後收到 LINE 私訊（附 PR 連結），到 GitHub 檢視並合併。
10. **群組也會收到回覆**：用 `/任務` 提出需求時，機器人立刻回覆「收到」；查詢有答案、修改完成或合併、需求被取消、處理遇到問題時，在群組回覆一則訊息（查詢答案直接貼在群組）。在「群組」頁的「在群組回覆」可改成「收到需求時也回覆」或「不在群組回覆」；「設定」頁的「在群組回覆」是總開關，關閉後所有群組都不回覆。「收到」使用 reply token，不計入推播額度；其他群組回覆會依群組人數計入 LINE 的每月推播額度。
    - **少等、少猜**：引用機器人的回答追問時，「收到」會附上同專案查詢的大約時間。群組裡的查詢回答只放重點；想看全文，「回覆」那則回答打「詳細」，機器人會分段回覆完整內容（不建任務、不用額度）。指令模式下 @機器人 也能提出需求。額度用完、每日次數用完或系統暫停時，群組會收到一則「已保留、之後自動繼續」的說明（同一群組 6 小時最多一則）。

本階段的常見答案僅供參考，尚未提供直接作答按鈕；回答仍用「補充需求」或既有群組補充流程。整份需求編輯會以新摘要為準，清除舊的結構化問題與假設標記；摘要中保留的假設文字仍屬需求。

完整操作與綁錯專案的處理方式見 [專案確認操作手順](project-confirmation.md)。

## 聊天室與觸發方式

- 開啟「聊天室」，選群組即可查看已收取的文字、圖片與任務狀態。按圖片可放大，按訊息下的任務名稱開啟詳情；「載入更早訊息」每次載入 50 則。
- 聊天室固定於視窗內，標題、群組選單與手機導覽保持可見，只有訊息區上下捲動。切換群組會停在最新訊息；載入較早訊息或刷新時保留正在閱讀的位置。
- 圖片需求：先傳圖片，再使用 LINE 的「回覆」引用該圖片，輸入 `/任務` 加上修改說明。系統只附上明確引用的同群組訊息，不會把附近無關圖片混入需求。引用已撤回、過期或尚未收到的內容時轉人工確認。
- `/任務` 必須在開頭，後接空白、換行、冒號或直接結束；`有人說 /任務`、`/任務清單` 不會觸發。指令仍須通過原有需求、風險與預算審核。
- 自動辨識仍由 AI 判斷意圖，閒聊與無需求的貼圖會略過；它無法保證永不誤判，想避免一般聊天派工請使用預設的指令模式。
- 本次升級將既有群組也設為指令模式，未辨識的舊訊息只保留供查看，既有任務不取消。之後切換模式僅影響新訊息；舊版設定呼叫省略模式會保留原值。
- **成員與權限**：看板以 GitHub 登入。擁有者（`ADMIN_GITHUB_ID`）固定為管理者；管理者可在「成員」頁以 GitHub 帳號加入同事，角色分為「成員」（收件匣、任務、聊天室，可核准、拒絕、採用方案、補充與重試任務）與「管理者」（另可管理群組、專案、系統、成員與設定）。不在名單上的帳號無法登入；移除成員會立即登出其所有裝置。任務操作紀錄寫入實際操作者的 GitHub 帳號。
- **通知鈴鐺**：看板右上角顯示與 LINE 私訊相同的重要通知（等待審核、需要處理、PR 已完成、查詢已回覆、額度用完、來源撤回），每人各自記錄已讀；可開啟瀏覽器桌面通知，看板開著時新通知會跳出。
- 聊天室唯讀，登入的成員皆可查看。發話者顯示 LINE 名稱：伺服器以群組成員資料 API 查詢並快取 7 天，LINE 使用者 ID 不回傳瀏覽器；查不到（成員已退出或未設定 Token）時退回群組內固定代號。名稱不納入備份，訊息到期清除發話者後一併刪除。不提供貼圖預覽。
- 群組名稱以 LINE 為準：背景工作以群組摘要 API 同步，新群組收到訊息後很快換成 LINE 名稱，之後每小時最多查一次；多人聊天室沒有名稱，查詢失敗時保留目前名稱。只顯示機器人已收到的內容，無法補抓入群前的歷史；原文及圖片保留設定天數（預設 30 天），撤回／到期後不再可讀。

## 查看 Codex 執行紀錄

登入管理看板，在「任務」或「待我審核」點開需求，即可看到「Codex 執行紀錄（唯讀）」。每次重試各自有執行 ID，可切換最近 50 次紀錄，查看需求版本、模型設定、目前／最後階段、開始／結束時間、期限及心跳。開發與獨立審查各有 Codex thread ID；容器 ID、命令結果、結束碼與失敗原因保存在事件中。

執行中會自動更新；「較早紀錄」每次讀取 200 筆，「回到最新」恢復即時檢視。進度斷線時會保留最後資料並標示中斷，不把斷線當作工作已結束。歷史任務沒有保存的 thread ID 或輸出無法補回。這是本系統的唯讀監看，不提供 Codex 終端機、提示詞輸入或遠端控制。

輸出先遮蔽常見憑證格式及網址中的認證／查詢參數，省略內部推理與完整提示詞。每個內容片段最多 6,000 字元，執行器每次工作最多保存 2,000 筆事件及截斷提示；原始內容跟隨來源撤回或到期清除，run_events 不進每日備份。

## 圖片上下文與來源證據

需求辨識會為實際參與的圖片保存畫面摘要、辨識文字、不確定事項及原始檔案 SHA-256。指令模式的一般圖片只供聊天室顯示，不額外呼叫辨識模型。啟用 RAG 後，圖片摘要可供跨日檢索；仍有效的原圖才會送交判讀。候選不唯一、找不到原圖或候選超過處理上限時須確認。

每個需求版本固定引用的圖片來源與雜湊，開發、唯一一次修復及獨立審查使用同組原圖；發布前再次檢查來源、群組及專案綁定。PNG、JPEG、WebP、GIF 須可實際解碼，單圖不超過 10 MB／4,000 萬像素，每次最多六張、合計 30 MB。GIF 只按首幀理解，來源雜湊仍指原始 GIF。

任務詳情顯示「圖片參考」及「上下文來源證據」，分開標示近期對話、直接引用、資料庫記憶、向量檢索及過往任務結果。可核對來源 ID、時間、命中分數、檔案行號與索引 SHA；提供給模型不等於模型確實採用或資料一定相關。原圖撤回／到期後，摘要、向量與可讀內容同步失效。圖片觀察及上下文證據不進每日備份，瀏覽器不會取得執行器憑證。
