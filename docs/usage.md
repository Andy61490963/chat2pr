# 使用指南

日常在 LINE 群組與看板上怎麼用。部署與維運見 [部署手冊](deployment.md) 與 [維運](operations.md)。

## 看板導覽

- **專案**：點專案名稱打開詳情。「概況」編輯、驗證或刪除專案；「環境驗證」看結果、回答補問；「連線與權限」設定完全存取、用白話描述資料庫連線、登記 SSH 主機；「記憶」維護專案記憶。
- **群組**：詳情裡「在群組回覆」上方直接寫出這個群組目前會收到哪些訊息；頁面下方有記憶總覽。額度用完時，成員可在群組打 `/進度` 補看。
- **設定**：會回覆的群組總數、需要處理的服務（展開「全部服務」看其他連線）與「使用摩擦」統計。「所有專案開放網路（不建議）」影響所有專案，建議改在個別專案開啟「完全存取」。
- **頁首警示**：你可收合需要留意的警示，重新整理後會維持收合，有新狀況時會再展開。LINE 本月推播額度用完時，可按「怎麼辦」查看替代做法。所有專案開放網路時，你可以在「設定」和「專案」查看狀態。

## 基本流程

1. 把這台伺服器的 LINE 機器人加進群組（每台伺服器各有自己的機器人），在看板「群組」頁勾選這個群組可以修改的專案。
2. 群組預設「指令與引用追問」：例如 `/任務 把首頁按鈕改成綠色，保留點擊功能`。安靜 1 分鐘（最長 5 分鐘）後，AI 整理需求並選擇專案；一般聊天只保存、不呼叫辨識模型。在「群組」頁可改選「自動辨識」。
3. **修改程式一律先確認目標專案**：收到 LINE 通知後，進看板任務詳情核對完整儲存庫、需求與理由，按「確認專案並核准修改」。只有一個綁定也不能省略確認。
4. 需求不夠明確時，AI 先區分可查證資訊、合理預設、必要問題與產品方向；只缺資訊時，任務詳情顯示一個問題與最多三個常見答案。程式碼可查的資訊交給執行階段；合理預設寫進摘要與「我先這樣假設」，可按「修改」直接調整單一假設，儲存成新版本並重新確認。只有修改的產品方向確實不同時才提供選項、推薦與理由；查詢不提供開發方案。LINE 只提供通知與看板連結，舊版採用按鈕也不會直接派工。
   - **在原地回答**：判讀或 Codex 執行中缺一件事時，機器人會在提出需求的群組發問（群組設定不回覆時只通知管理者）。群組成員點提問下方的常見答案按鈕、用 LINE「回覆」那則提問直接作答，或在看板任務詳情點常見答案、輸入後按「送出回答」。系統把問答併進需求成為新版本：查詢照原本規則直接繼續，修改需求仍要管理者確認。回答含密碼、金鑰等憑證格式時不會被收下：機器人回覆「沒有收下，也不會交給 AI」，原文不保存、也不送判讀；請收回那則訊息，機密改由管理者在看板輸入。
   - 已回答的查詢修改「我先這樣假設」時，按「依新假設接著問」會建立新的一題並保留原回答；新題沿用原專案、分支與對話串，索取機密實際值時仍要等人工確認。尚未回答的任務則修改原需求並產生新版本。
5. 只想查資料、問問題時，AI 會建立**查詢任務**：本次明確指名唯一專案，或有唯一有效檔案證據時可自動執行；其餘先到看板確認。報告顯示於看板、GitHub Issue 及 LINE，不開 PR；查詢時的專案、分支與版本在看板任務詳情展開查看。切換查詢／修改類型會作廢舊核准。
   - **指名寫法**：完整儲存庫（`example-org/OrderService`）、專案名稱，以及在已登記專案中唯一、至少 6 個字的儲存庫名稱（`OrderService`）或去掉結尾括號的專案名稱都算。
   - **風險**：查詢在隔離容器唯讀執行，回答會遮蔽機密，所以詢問權限、部署、密碼儲存方式等功能怎麼運作不會被擋；只有要求交出密碼、金鑰、token、連線字串等機密的實際值時，才等人工確認。AI 對查詢列出的風險記在活動紀錄當提醒。修改任務一律人工確認，規則不變。
   - **跨專案查詢**：明確指名多個已綁定本群組的專案時（例如比對兩個專案的欄位），可自動執行；其他專案設定分支的最新版本會唯讀放在 `/agentflow/env/projects/<儲存庫名稱>`，你可在任務詳情展開「查詢時的專案、分支與版本」，查看這次查詢使用的各個專案與版本。指名未綁定的專案仍會擋下。
   - **安裝依賴**：失敗時自動重試一次；查詢重試仍失敗時改以閱讀程式碼回答，並在報告註明哪些部分未實際執行。修改任務重試仍失敗就停止。
   - **追問**：查詢回答後可以接著問，不用再寫專案名稱。
     - 在 LINE 用「回覆」引用同群組機器人的任務回答後輸入問題，例如「那 ch3 呢？」；指令模式也不必加 `/任務`，並會立即回覆收到。或在看板任務詳情的「接著問」輸入。
     - 待判讀訊息全是這類文字追問時，安靜 5 秒後即可排程；混有一般需求或圖片時，維持安靜 60 秒／最長 300 秒。實際開始仍受佇列與額度限制。
     - 系統會建立新的一題，沿用上一題的專案與分支，並把前面的問答交給 Codex，原本的回答會保留。
     - 沒有引用時，AI 會判斷是不是接續 7 天內的某一題；有指名其他專案就不沿用。
     - 索取機密實際值的追問一樣要等人工確認。對話串沒有題數上限；交給 Codex 時，最近 5 題給完整問答，更早的只給問題與「先看重點」。
     - 接錯題時，在 LINE 改引用正確的那則回答，或在看板任務詳情的「接錯題了？」選「改成接在另一題後面」（或改成新話題），系統會重新處理。
     - 看板的「修改這一題」會**取代**原回答，只在想換個問法整個重查時使用。
6. 分不清專案時，你可以在收件匣或任務詳情指定專案。系統最多會建議兩個已驗證、已啟用但尚未綁定的專案，你可以查看理由與引用訊息。管理者按「綁定並指定這個專案」後，群組會新增綁定，任務會指定到該專案並留下活動紀錄。你仍可更換專案，並須確認需求與分支才能排程。需要留下長期規則時，你可以在指定已綁定專案時勾選「記住」（預設不勾），也可以說「`/任務 記住：庫存相關都改範例倉庫`」。群組記憶僅供判讀參考。
7. 專案開發規範可在群組提出，例如「`/任務 記住：MES 前端不要用 jQuery`」；系統建立修改 `AGENTS.md` 的待確認任務，確認專案後才執行並開 PR。
8. 自動辨識可彙整零碎聊天；指令模式的補充需以 `/任務` 開頭，或引用同群組機器人的任務通知。AI 會讀近三天對話作為背景，但只有符合觸發規則的訊息才能提出新工作。話還沒說完會先等，補充尚未開始的需求會併入同一張任務；修改任務仍須確認新版本。
9. PR 完成後收到 LINE 私訊（附 PR 連結），到 GitHub 檢視並合併。
   - **已回覆**：如果 Codex 確認目前的內容已符合所有驗收條件，且沒有收集到變更，系統會依通知設定對群組和管理者送出同一句「已經符合需求，沒有需要修改的地方」。你可以在看板的「修改結果」查看 Codex 的判斷依據。這次不會開 PR。如果 Codex 做不到或無法確認需求已符合，你會在看板看到「需要處理」及原因。
   - **再改一點**：PR 開出後想再調整，在 LINE「回覆」機器人的完成通知說明要改什麼，或在看板任務詳情的「再改一點」輸入。你確認新的一題後：
     - PR 還沒合併：Codex 以 PR 目前的內容為基底繼續改，推到同一個分支、更新同一個 PR，不會出現第二個 PR；
     - 已合併：從目標分支另開 PR，並帶入原需求與原 PR 的脈絡；
     - 原需求還在處理中：追加會等它完成再接上。
     - PR 分支在這段期間被別人推了新提交時會停下來，不覆寫他人的修改，請重新確認後再追加。
10. **群組也會收到回覆**：用 `/任務` 提出需求時，機器人立刻回覆「收到」；查詢有答案、修改完成或合併、需求被取消、處理遇到問題時，在群組回覆一則訊息（查詢答案直接貼在群組）。在「群組」頁的「在群組回覆」可改成「收到需求時也回覆」或「不在群組回覆」；「設定」頁的「在群組回覆」是總開關，關閉後所有群組都不回覆。「收到」使用 reply token，不計入推播額度；其他群組回覆會依群組人數計入 LINE 的每月推播額度。
    - **少等、少猜**：引用機器人的回答追問時，「收到」會附上同專案查詢的大約時間。群組裡的查詢回答只放重點；想看全文，「回覆」那則回答打「詳細」，機器人會分段回覆完整內容（不建任務、不用額度）。指令模式下 @機器人 也能提出需求。額度用完、每日次數用完或系統暫停時，群組會收到一則「已保留、之後自動繼續」的說明（同一群組 6 小時最多一則）。
    - **「收到」依目前狀態說明**：系統暫停或暫停整理新需求、這個群組的需求判讀連續出錯而暫停（管理者排除問題後在群組頁按「重新辨識」）、群組沒有可處理需求的專案（未綁定，或專案正在重新驗證）、Codex 訂閱額度用完時，「收到」會直接說明需求已保留、恢復後自動處理，不用重新提出，不再承諾「處理完會在這裡回報」。推播額度用完或有回覆沒送到時，「收到」後面多一句「有 N 則先前沒送達的回覆，打 /進度 取回」。
    - **`/進度`**：在群組輸入 `/進度`，機器人用 reply token 回覆，不耗推播額度、不建任務、不呼叫 AI。第一則是這個群組還沒結束或 7 天內有變動的需求與狀態；接著最多 4 則先前沒送到的回覆（查詢答案、待回答的問題、完成通知等，限 7 天內、每個需求只送最新一則），還有更多時最後一則寫「還有 N 則，再輸入 /進度」。補送的查詢答案一樣可以「回覆」打「詳細」看全文，補送的問題也可以直接「回覆」作答。只看得到本群組的內容；`/進度` 必須在開頭，`/進度表` 不會觸發。群組停用時回覆「沒有啟用」，選擇不在群組回覆或關閉總開關時不回覆。某則回覆用 `/進度` 補送兩次都被 LINE 拒收時就不再補送（看板通知寫「以 /進度 補送多次失敗，已停止補送，請管理者在看板查看並手動轉達」），之後的 `/進度` 照常回需求摘要與其他回覆。

群組裡的補問有常見答案時，訊息下方會出現對應的按鈕，群組成員直接點按鈕就能作答，也可以用 LINE「回覆」那則提問輸入答案；兩種方式的權限相同，修改需求仍要管理者確認。按鈕在群組有新訊息後就會消失，這時改用「回覆」作答即可；需求已改版或已有人回答時，點舊按鈕會收到「這題已經回答過或需求已更新」。LINE 推播額度用完時，補問與按鈕都送不出去，請在看板任務詳情作答（或在群組打 `/進度` 取回補問後「回覆」作答）。

用 `/任務` 提出的訊息被判成和既有需求重複、要求記住的規則，或沒有看到要處理的事項時，群組也會收到一則說明（例如「這則和「…」是同一件事」「已記住：…」）。這些說明是推播，會計入推播額度；額度用完時延後送出，過期就不再補送。自動辨識模式下的一般聊天不會收到這類說明，AI 自行歸納的記憶也不會。

整份需求編輯會以新摘要為準，清除舊的結構化問題與假設標記；摘要中保留的假設文字仍屬需求。

完整操作與綁錯專案的處理方式見 [專案確認操作手順](project-confirmation.md)。

## 收件匣

- 任務或專案驗證失敗時，你可以依「建議」到專案頁操作；需要重新驗證時，建議會顯示該專案的驗證按鈕名稱。
- **數字是實際數量**：「需要你處理」「進行中」「待合併」只在各自的區塊標題顯示數量，你可點標題前往對應的任務清單。「近 7 天已合併」（臺北時間）與「累計 N 個需求」顯示在任務區塊下方；「任務」頁的分頁數字也以資料庫的實際數量為準。
- **最近動態**：你可以查看任務進度與管理者操作，查詢開始時會顯示「開始調查」。按「顯示系統紀錄」可查看工作映像、套件審查、檢索參考等細節。
- **任務頁**：你第一次開啟時會看到「進行中與待處理」，包含待審核、需要處理、等待額度、排程、開發、驗證與待合併的任務。清單空白時可按「看已結束的任務」。每列都會標示「修改」或「查詢」。
- **查找舊任務**：「已結束」與「全部」預設按更新時間從新到舊，每批最多 30 筆。你可以捲到清單底部或按「載入更多任務」接著看。群組、專案和搜尋會先篩選整份清單，再分批載入，你也可以選擇依專案或群組分組。
- **保留篩選**：同一個帳號下次用同一瀏覽器開啟任務頁時，會沿用你選過的分頁、群組、專案、分組方式及搜尋字詞。有指定篩選的連結會依網址顯示。
- **需要你處理**：只放待審核與失敗的任務。主按鈕依失敗原因：設定、環境、專案類先「前往」對應頁面（成員看不到管理頁，改按「詳情」）；逾時先「修改這一題」把需求改小；其他直接「重試」。都可以按「結束任務」。進行中可按「停止並結束」，之後可在任務詳情「重新開啟」。
- **等待額度（會自動繼續）**：額度或每日次數達上限而保留的工作另列在下方，不算在「需要你處理」與分頁標題數字裡，「任務」頁有「等待額度」分頁。今日執行次數達上限時，工作會在臺北午夜後或你提高每日次數後自動繼續。API 模式預估額度不足時，工作會在隔日自動繼續，也可以按「已提高預算，立即再試」。
- **Codex 訂閱額度**：你可以在設定頁的「Codex 訂閱額度」卡片將「保留給你個人使用」設為 0–90%，預設 0%。例如保留 60% 時，任一額度視窗用到 40% 就會保留判讀、開發、驗證與查詢。看板會顯示 chat2pr 已達可用上限、你保留的比例與重置時間；額度重置或你調低保留比例，系統確認可用後會自動繼續。遇到網路或登入問題而無法確認用量時，系統會定期重新檢查。
- **進行中**：開發或驗證中的任務顯示目前階段、已跑多久與期限，例如「Codex 修改程式・已 12 分／期限 14:30」，每 30 秒更新；服務心跳超過 30 秒沒更新時改顯示「狀態待確認」。打開執行中的任務，詳情預設在「執行紀錄」分頁，標頭也有同一行進度；執行紀錄停在最底下時，新事件進來會自動捲到最新，往上翻閱時不會被拉走。

## 聊天室與觸發方式

- 開啟「聊天室」，選群組即可查看已收取的文字、圖片與任務狀態。按圖片可放大，按訊息下的任務名稱開啟詳情；「載入更早訊息」每次載入最多 50 則成員訊息與 200 則機器人訊息；同一段時間機器人訊息超過 200 則時會少載一些成員訊息，兩則成員訊息之間仍超過 200 則時，再按一次會接著載入較舊的機器人訊息，不會遺漏。
- 聊天室固定於視窗內，標題、群組選單與手機導覽保持可見，只有訊息區上下捲動。切換群組會停在最新訊息；載入較早訊息或刷新時保留正在閱讀的位置。
- **機器人的群組訊息**：機器人推播到群組的查詢回答、補問、失敗說明、定期檢查回報等也會依時間排在聊天室裡，以淺綠底色與「機器人」標示，旁邊的標籤是送達狀態：「已送出」「等待送出」「額度不足，未送出」（LINE 本月推播額度已用完，會一直排隊到額度恢復）「補送中」（成員打 `/進度`，正在用回覆補送）「送不出去」（重試 3 次仍失敗）「未送出」（群組回覆已關閉、已過期或已有較新的回覆，不會再送）。沒送到的訊息有「複製文字」按鈕，可以手動貼到 LINE 群組代為轉達；超過保留天數的只顯示「原文已到期」，不能複製。成員在 LINE 用「回覆」引用機器人的訊息時，聊天室顯示「回覆 機器人：…」。
- 機器人用 reply token 回的「收到」與 `/進度` 的進度摘要不留紀錄，不會出現在聊天室；`/進度` 順便補送的舊回覆本來就是群組訊息，會照常出現並改標「已送出」。
- 任務詳情也會標示這個任務的查詢回答、補問或失敗說明是否已送到群組；沒送到時附「複製群組訊息」。補問沒送到時，可以直接在任務詳情「送出回答」，或複製後貼到群組請成員回覆。
- 圖片需求：先傳圖片，再使用 LINE 的「回覆」引用該圖片，輸入 `/任務` 加上修改說明。系統只附上明確引用的同群組訊息，不會把附近無關圖片混入需求。引用已撤回、過期或尚未收到的內容時轉人工確認。
- `/任務` 必須在開頭，後接空白、換行、冒號或直接結束；`有人說 /任務`、`/任務清單` 不會觸發。指令仍須通過原有需求、風險與預算審核。
- 自動辨識會略過閒聊、沒有需求的貼圖、指派同事或自己承接的工作，以及對全體成員的工作公告。仍在討論、尚未定案或向同事徵詢意見時，系統會先等更多訊息，到期仍未定案就略過。對話中已確定、可重複使用的群組規則，可以存為群組記憶。
- 你可以用 `/任務`、提及機器人或引用機器人的任務通知提出明確需求，也可以直接說明需要做什麼而不指定處理人。管理者可在「最近動態」按「顯示系統紀錄」，查看 AI 未建立任務的原因。
- 本次升級將既有群組也設為指令模式，未辨識的舊訊息只保留供查看，既有任務不取消。之後切換模式僅影響新訊息；舊版設定呼叫省略模式會保留原值。
- **成員與權限**：看板以 GitHub 登入。擁有者（`ADMIN_GITHUB_ID`）固定為管理者；管理者可在「成員」頁以 GitHub 帳號加入同事，角色分為「成員」（收件匣、任務、聊天室，可核准、拒絕、採用方案、補充與重試任務）與「管理者」（另可管理群組、專案、系統、成員與設定）。不在名單上的帳號無法登入；移除成員會立即登出其所有裝置。任務操作紀錄寫入實際操作者的 GitHub 帳號。
- **通知鈴鐺**：清單先列需要你處理的事項，同一任務只計一次。鈴鐺的數字包含收件匣「需要你處理」的任務、其他待辦（例如待合併的 PR 或專案補問），以及你還沒看過的結果。打開鈴鐺會把結果標為你已讀，待辦會保留到你處理完。你確認或結束任務、合併 PR、回答專案補問後，原提醒會自動視為已讀。管理者可看管理私訊全文。成員可看通知種類、相關任務標題與任務動態，點選任務可查看詳情。無任務的管理稽核只顯示給管理者。群組通知在聊天室的原文保留期限內可閱讀，到期後顯示「原文已到期」。開啟瀏覽器桌面通知後，看板開著時會提醒新通知。
- 聊天室唯讀，登入的成員皆可查看。發話者顯示 LINE 名稱：伺服器以群組成員資料 API 查詢並快取 7 天，LINE 使用者 ID 不回傳瀏覽器；查不到（成員已退出或未設定 Token）時退回群組內固定代號。名稱不納入備份，訊息到期清除發話者後一併刪除。不提供貼圖預覽。
- 群組名稱以 LINE 為準：背景工作以群組摘要 API 同步，新群組收到訊息後很快換成 LINE 名稱，之後每小時最多查一次；多人聊天室沒有名稱，查詢失敗時保留目前名稱。只顯示機器人已收到的內容，無法補抓入群前的歷史；原文及圖片保留設定天數（預設 30 天），撤回／到期後不再可讀。

## 查看 Codex 執行紀錄

登入管理看板，在「任務」或「待我審核」點開需求，即可看到「Codex 執行紀錄（唯讀）」。每次重試各自有執行 ID，可切換最近 50 次紀錄，查看需求版本、模型設定、目前／最後階段、開始／結束時間、期限及心跳。開發與獨立審查各有 Codex thread ID；容器 ID、命令結果、結束碼與失敗原因保存在事件中。

執行中會自動更新；「較早紀錄」每次讀取 200 筆，「回到最新」恢復即時檢視。進度斷線時會保留最後資料並標示中斷，不把斷線當作工作已結束。歷史任務沒有保存的 thread ID 或輸出無法補回。這是本系統的唯讀監看，不提供 Codex 終端機、提示詞輸入或遠端控制。

輸出先遮蔽常見憑證格式及網址中的認證／查詢參數，省略內部推理與完整提示詞。每個內容片段最多 6,000 字元，執行器每次工作最多保存 2,000 筆事件及截斷提示；原始內容跟隨來源撤回或到期清除，run_events 不進每日備份。

## 圖片上下文與來源證據

需求辨識會為實際參與的圖片保存畫面摘要、辨識文字、不確定事項及原始檔案 SHA-256。指令模式的一般圖片只供聊天室顯示，不額外呼叫辨識模型。啟用 RAG 後，圖片摘要可供跨日檢索；仍有效的原圖才會送交判讀。候選不唯一、找不到原圖或候選超過處理上限時須確認。

每個需求版本固定引用的圖片來源與雜湊，開發、唯一一次修復及獨立審查使用同組原圖；發布前再次檢查來源、群組及專案綁定。PNG、JPEG、WebP、GIF 須可實際解碼，單圖不超過 10 MB／4,000 萬像素，每次最多六張、合計 30 MB。GIF 只按首幀理解，來源雜湊仍指原始 GIF。

任務詳情顯示「圖片參考」及「上下文來源證據」，分開標示近期對話、直接引用、資料庫記憶、向量檢索及過往任務結果。可核對來源 ID、時間、命中分數、檔案行號與索引 SHA；提供給模型不等於模型確實採用或資料一定相關。原圖撤回／到期後，摘要、向量與可讀內容同步失效。圖片觀察及上下文證據不進每日備份，瀏覽器不會取得執行器憑證。
